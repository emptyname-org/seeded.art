# Operational metrics

`GET /health/metrics` on each loopback listener returns JSON schema 1. Caddy blocks `/health*` publicly. Responses are `no-store`; health requests do not count as traffic.

Counters restart with `process_start`. Compute deltas separately for each origin and discard deltas across restarts. Snapshots are approximate under concurrent traffic.

- `requests`: responses reaching headers, by status and fixed route class; cancellations before headers counted separately.
- `active`: requests through body consumption/drop, plus peak concurrency.
- `latency_ms`: time to headers. Counts are exclusive buckets with the final overflow bucket; they exclude body delivery time.
- `body`: errors and bytes yielded to the server stack, not confirmed network transfers.
- `cache`: successful local lookups, misses, actual upstream HTTP attempts/errors, eviction count and charged disk quota. `retention_skipped` counts verified upstream results that could not acquire scratch or a memory-copy worker; their response still succeeds. Each content resolution counts its local lookup once, including memory, mirror and disk. Implicit redirects count as one attempt. Upstream errors exclude 404; cancellation before a reply is not an upstream error.
- `mirror.hits`: direct mirror reads; subsequent memory hits count only under cache.
- `local_delivery`: body-byte reservations (512 MiB by default), current charged bytes, wait count/capacity (256), cumulative waits, timeouts and rejected admissions. A local miss is probed before body reservation; returned bodies reserve their actual size and remain charged until the last shared clone drops. Cache-hit waiters hold allocation metadata only; cold decoded bodies stay under their scratch reservation while awaiting delivery. The two-second local budget covers admission waits only, not disk probes, reads, copies or waiting for an existing lookup. `leader_waits`, `leader_timeouts` and `leader_rejected` separately count allocation-leader admission. Reservations are not unique RAM usage. `reclaim_scans`, `reclaimed` and `reclaim_no_victim` count pressure scans (at most one per 250 ms, only while connections are registered), connections cancelled, and scans cancelling none (including progress races).
- `local_scratch`: decode/verification working-byte reservations (at least 512 MiB, increased if configured object limits need more), upstream retention copies, current usage, wait count/capacity (256), waits, timeouts and rejected admissions. Scratch admission precedes body allocation; its `leader_*` and reclaim fields stay zero.
- `local_reads`: active local read workers, waiting reads, queue capacity, waits, timeouts and rejections. Same-key followers use a separate 256-place queue for at most five seconds, without reader or scratch slots. Its `leader_waiting`, `leader_wait_capacity`, `leader_waits`, `leader_timeouts` and `leader_rejected` count current queue usage, capacity and admission events separately. The existing cohort shares successful bodies, misses and transient busy errors. A cancelled, panicked or I/O-failed leader lets one follower at a time retry; later arrivals start a fresh generation. `coalesced` counts requests joining an existing generation; `coordination_rejected` counts failures to create one (272 concurrent generations, including completed results still held by followers). `shared_failures` counts failed follower responses reusing a cohort error, once per response. `deadline_expired` counts only the request exhausting its own admission budget before a later stage starts; shared errors and that stage do not add another expiry or pool timeout.
- `resolution`: `upstream_failures` and `local_failures` count only `Unavailable` (503); `upstream_other_failures` and `local_other_failures` count other terminal errors. `upstream_busy` counts resolver/HTTP admission failures and gateway cooldown events, including retries that later succeed. `upstream_timeouts` counts overall resolver deadlines, including those returning a verified fallback. `mirror_busy` counts mirror-reader admission failures. These diagnostic counters overlap; do not sum them as unique failed requests.
- `artwork_admission` (artwork origin only): `metadata_waiting_full`, `metadata_waiting_timeout`, `metadata_query_timeout` and `metadata_query_unavailable` (metadata admission/query failures; HTTP 503); `handler_timeout` (40 s handler deadline; 503); `upstream_waiting_full` and `upstream_waiting_timeout` (upstream queue full or assembly-slot timeout; 503); `transform_timeout` (worker-slot timeout; 503); `delivery_client_table_full` and `delivery_global_bytes_full` (client registry full or active/pending response-byte or waiter limit; 503); `delivery_client_bytes_full` (per-client response-byte limit; 429). These count limiter events, not unique failed requests; resolution counters overlap them. Fixed error bodies preserve their status and bypass delivery-byte accounting. `delivery_reclaim_scans`, `delivery_reclaimed` and `delivery_reclaim_no_victim` report the web delivery pool using the same definitions as `local_delivery`.
- `request_limits` (per listener): `global_content_wait_full` (global wait queue full; 503), `client_content_wait_full` (per-client content wait queue full; 429), `content_wait_timeout` (10 s content admission deadline; 429), `noncontent_bucket_rejected` (request rate or in-flight cap; 429), `family_new_client_rejected` (compatibility field, always zero), `noncontent_stream_timeout` (10 s stream-slot wait; 429), `client_table_full` (address table cannot evict an active entry; 429), and `missing_client_ip` (transport identity missing; 503). The app and artwork listeners have separate snapshots; no client identifiers are exposed.

- `database_admission` (app origin): `waiting_full`, `waiting_timeout`, `query_timeout`, `query_unavailable`. They count the 512-waiter queue, two-second admission deadline, five-second query deadline, and unavailable archive reads respectively. Includes readiness reads; excludes successful queries. Artwork metadata uses its separate counters.

Content and artwork fields appear only when attached on the artwork origin. Unavailable disk accounting is `null`. Unsupported counters are omitted. No IPs, addresses, identifiers, query strings or arbitrary route labels are retained.
